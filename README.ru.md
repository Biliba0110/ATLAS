# ATLAS

Языковые версии: [English](README.md) | [Українська](README.uk.md) | [Русский](README.ru.md)

ATLAS — self-hosted IPAM и легкий реестр сети для home-lab, небольших команд и растущих внутренних сетей.

## Что делает ATLAS

- управляет подсетями с `CIDR`, пулами, заметками и, при необходимости, группами доступа
- поддерживает именованные диапазоны IP внутри подсети
- хранит устройства с `name`, `IP`, необязательным `MAC`, `type` и заметками
- подсказывает свободный IP на основе базы и, при необходимости, `ping`
- определяет конфликты IP
- ведет историю изменений IP
- поддерживает многопользовательский доступ с ролями и группами доступа
- импортирует и экспортирует данные через `JSON`, `CSV` и полный `backup`

## Быстрый старт

```bash
python3 server.py
```

Открыть:

- `http://localhost:4173`
- `http://<server-ip>:4173`

При первом чистом запуске создается bootstrap-аккаунт:

- логин: `Admin`
- пароль: `Atlas`

После первого входа пароль нужно сменить.

## Как использовать

Базовый сценарий:

1. Добавить подсеть.
2. При необходимости создать группы диапазонов внутри подсети.
3. Добавить устройства вручную.
4. Использовать поиск, фильтры и историю для контроля занятости.
5. Делать экспорт или backup по мере необходимости.

## Пользователи и доступ

- `admin` — полный доступ, пользователи, группы доступа, серверные настройки
- `editor` — чтение и запись разрешенных данных
- `viewer` — только чтение

Группы доступа определяют видимость:

- подсеть может быть публичной или ограниченной группой доступа
- `admin` видит всё
- не-админы видят публичные подсети и те, что назначены их группам

## Ping и автоматизация

`ping` в ATLAS — это сигнал занятости, а не полноценное сетевое обнаружение.

Используется для:

- более безопасного подбора свободного IP
- точечной проверки подсетей
- выявления адресов, которые уже могут быть заняты

Рекомендуемая практика:

- включать авто-скан только для тех подсетей, которые достижимы с сервера ATLAS
- отключать его для удаленных или изолированных сетей, где `ping` не дает надежный результат

## Импорт, экспорт и backup

Поддерживаемые форматы:

- `JSON` — снимок состояния ATLAS
- `CSV` — отдельные выгрузки для подсетей, диапазонов и устройств
- `Backup ATLAS` — полный backup для восстановления или переноса

Если нужен полный перенос экземпляра вместе с пользователями, настройками и моделью доступа, лучше использовать именно `Backup ATLAS`.

## Хранение данных

ATLAS хранит общее состояние в серверной `SQLite`.

- путь к базе по умолчанию: `data/atlas.db`
- база создается автоматически
- к одному экземпляру ATLAS могут подключаться несколько устройств

## Конфигурация

Переменные окружения:

- `ATLAS_HOST` — bind address, по умолчанию `0.0.0.0`
- `ATLAS_PORT` — порт, по умолчанию `4173`
- `ATLAS_DB_PATH` — путь к базе, по умолчанию `data/atlas.db`
- `ATLAS_SCAN_INTERVAL` — интервал фонового сканирования в секундах, по умолчанию `90`
- `ATLAS_SCAN_TIMEOUT_MS` — таймаут одного ping, по умолчанию `1000`
- `ATLAS_SCAN_CONCURRENCY` — параллельность ping, по умолчанию `32`
- `ATLAS_HISTORY_LIMIT` — число записей истории для UI, по умолчанию `200`

Пример:

```bash
ATLAS_PORT=4180 python3 server.py
```
