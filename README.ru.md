# ATLAS

Языковые версии: [English](README.md) | [Українська](README.uk.md) | [Русский](README.ru.md)

ATLAS — self-hosted IPAM и легкий inventory инфраструктуры для home-lab, небольших команд и растущих внутренних сетей.

`ATLAS — инфраструктура под контролем, без лишней сложности.`

## Возможности

- управление подсетями с `CIDR`, пулом адресов, заметками и, при необходимости, группами доступа
- именованные диапазоны IP внутри подсети
- ручной реестр устройств с `name`, `IP`, необязательным `MAC`, `type` и заметками
- подсказка свободного IP на основе данных базы и `ping`
- обнаружение конфликтов IP
- история изменений IP
- live-обновления интерфейса
- импорт и экспорт через `JSON` и `CSV`
- многопользовательский доступ с ролями и группами доступа
- серверное хранение пользовательских настроек и шаблонов автоподстановки

## Стек

- `Python 3`
- `SQLite`
- `HTML / CSS / Vanilla JavaScript`
- `Server-Sent Events`

## Быстрый старт

```bash
python3 server.py
```

Открыть:

- `http://localhost:4173`
- `http://<server-ip>:4173`

При первом чистом запуске создается bootstrap-аккаунт:

- логин: `Admin`
- пароль: `Atlas`

После первого входа пароль нужно сменить.

## Хранение данных

ATLAS хранит общее состояние в серверной `SQLite`.

- путь к базе по умолчанию: `data/atlas.db`
- база создается автоматически
- к одному экземпляру ATLAS могут подключаться несколько устройств

Хранятся подсети, диапазоны, устройства, результаты сканирования, история, пользователи, сессии, группы доступа и пользовательские настройки.

## Модель доступа

- `admin` — полный доступ, пользователи, группы доступа, серверные настройки
- `editor` — чтение и запись разрешенных данных
- `viewer` — только чтение

Группы доступа определяют видимость:

- подсеть может быть публичной или ограниченной группой доступа
- `admin` видит всё
- не-админы видят публичные подсети и те, что назначены их группам

## Ping и сканирование

`ping` в ATLAS — это легкий сигнал занятости, а не полноценное сетевое обнаружение.

Он используется для:

- выявления адресов, которые уже могут быть заняты
- более безопасного подбора свободного IP
- точечной проверки подсетей

Это не замена DHCP, ARP, SNMP или полного discovery.

Текущая логика:

- фоновое сканирование работает с заданным интервалом
- в фоне проверяются только подсети, включенные в автоматизацию
- новые подсети могут наследовать политику сканирования по умолчанию
- проверку можно запускать точечно для конкретной подсети из реестра
- при создании группы возможен отдельный scan только для ее диапазона

## Импорт и экспорт

Поддерживаемые форматы:

- `JSON` — полный снимок состояния
- `CSV` — отдельные выгрузки для подсетей, диапазонов и устройств

Импорт может либо объединять данные, либо полностью заменять текущее состояние.

## Конфигурация

Переменные окружения:

- `ATLAS_HOST` — bind address, по умолчанию `0.0.0.0`
- `ATLAS_PORT` — порт, по умолчанию `4173`
- `ATLAS_DB_PATH` — путь к базе, по умолчанию `data/atlas.db`
- `ATLAS_SCAN_INTERVAL` — интервал фонового сканирования в секундах, по умолчанию `90`
- `ATLAS_SCAN_TIMEOUT_MS` — таймаут одного ping, по умолчанию `1000`
- `ATLAS_SCAN_CONCURRENCY` — параллельность ping, по умолчанию `32`
- `ATLAS_HISTORY_LIMIT` — число записей истории для UI, по умолчанию `200`

Пример:

```bash
ATLAS_PORT=4180 python3 server.py
```
