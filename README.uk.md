# ATLAS

Мовні версії: [English](README.md) | [Українська](README.uk.md) | [Русский](README.ru.md)

ATLAS — self-hosted IPAM і легкий inventory інфраструктури для home-lab, невеликих команд і внутрішніх мереж, що ростуть.

`ATLAS — інфраструктура під контролем, без зайвої складності.`

## Можливості

- керування підмережами з `CIDR`, пулом адрес, нотатками та, за потреби, групами доступу
- іменовані діапазони IP всередині підмережі
- ручний реєстр пристроїв з `name`, `IP`, необов'язковим `MAC`, `type` і нотатками
- підказка вільного IP на основі даних бази та `ping`
- виявлення конфліктів IP
- історія змін IP
- live-оновлення інтерфейсу
- імпорт та експорт через `JSON` і `CSV`
- багатокористувацький доступ з ролями та групами доступу
- серверне зберігання користувацьких налаштувань і шаблонів автопідстановки

## Стек

- `Python 3`
- `SQLite`
- `HTML / CSS / Vanilla JavaScript`
- `Server-Sent Events`

## Швидкий старт

```bash
python3 server.py
```

Відкрити:

- `http://localhost:4173`
- `http://<server-ip>:4173`

Під час першого чистого запуску створюється bootstrap-акаунт:

- логін: `Admin`
- пароль: `Atlas`

Після першого входу пароль потрібно змінити.

## Зберігання даних

ATLAS зберігає спільний стан у серверній `SQLite`.

- типовий шлях до бази: `data/atlas.db`
- база створюється автоматично
- до одного інстансу можуть підключатися кілька пристроїв

Зберігаються підмережі, діапазони, пристрої, scan-результати, історія, користувачі, сесії, групи доступу та користувацькі налаштування.

## Модель доступу

- `admin` — повний доступ, користувачі, групи доступу, серверні налаштування
- `editor` — читання та запис дозволених даних
- `viewer` — лише читання

Групи доступу визначають видимість:

- підмережа може бути публічною або обмеженою групою доступу
- `admin` бачить усе
- не-адміни бачать публічні підмережі та ті, що призначені їхнім групам

## Ping і сканування

`ping` у ATLAS — це легкий сигнал зайнятості, а не повноцінне мережеве виявлення.

Він використовується для:

- виявлення адрес, які вже можуть бути зайняті
- безпечнішого підбору вільного IP
- точкової перевірки підмереж

Це не заміна DHCP, ARP, SNMP або повного discovery.

Поточна логіка:

- фонове сканування працює з заданим інтервалом
- у фоні перевіряються лише дозволені для автоматизації підмережі
- нові підмережі можуть успадковувати типову політику сканування
- перевірку можна запускати точково для конкретної підмережі з реєстру
- під час створення групи можливий окремий scan тільки для її діапазону

## Імпорт та експорт

Підтримувані формати:

- `JSON` — повний знімок стану
- `CSV` — окремі вивантаження для підмереж, діапазонів і пристроїв

Імпорт може або об'єднувати дані, або повністю замінювати поточний стан.

## Конфігурація

Змінні середовища:

- `ATLAS_HOST` — адреса прив'язки, типово `0.0.0.0`
- `ATLAS_PORT` — порт, типово `4173`
- `ATLAS_DB_PATH` — шлях до бази, типово `data/atlas.db`
- `ATLAS_SCAN_INTERVAL` — інтервал фонового сканування в секундах, типово `90`
- `ATLAS_SCAN_TIMEOUT_MS` — таймаут одного ping, типово `1000`
- `ATLAS_SCAN_CONCURRENCY` — паралельність ping, типово `32`
- `ATLAS_HISTORY_LIMIT` — кількість записів історії для UI, типово `200`

Приклад:

```bash
ATLAS_PORT=4180 python3 server.py
```
