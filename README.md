# HomeLab IPAM

IPAM для домашней лаборатории с серверной `SQLite`-базой, веб-интерфейсом и базовой автоматизацией из версии `0.2`.

## Версия 0.2

Цель этой версии: уменьшить ручную работу и быстрее понимать, какие IP уже заняты в подсети.

Что уже реализовано:

- добавление подсетей с `CIDR`, пулом адресов и комментариями
- добавление именованных диапазонов внутри подсети, например `hypervisor 2-4` или `VM 5-19`
- ручное добавление устройств: имя, IP, необязательный `MAC`, тип, комментарий
- автоматическая проверка занятых IP через `ping`
- отдельная проверка занятости сразу после создания группы диапазона
- подсказка первого свободного IP при добавлении устройства
- проверка конфликтов IP на основе записей в базе и результатов `ping`
- история IP-событий: кто, когда и для какого устройства создал или удалил запись
- live-обновления интерфейса через `Server-Sent Events`
- поиск по `IP`, `MAC`, имени, типу, подсети и группе диапазона
- экспорт в `JSON` и `CSV`
- импорт из `JSON` и `CSV`
- общий серверный state для всех клиентов, которые открывают один и тот же IPAM

## Запуск

```bash
python3 server.py
```

После запуска открой:

- `http://localhost:4173` на той же машине
- `http://<IP_сервера>:4173` с других устройств в сети

Если сервер уже работал и ты обновил код, перезапусти `server.py`, чтобы новая логика API и сканирования применилась.

## Настройки окружения

- `IPAM_HOST` — адрес bind, по умолчанию `0.0.0.0`
- `IPAM_PORT` — порт, по умолчанию `4173`
- `IPAM_DB_PATH` — путь к базе, по умолчанию `data/ipam.db`
- `IPAM_SCAN_INTERVAL` — интервал фонового `ping`-сканирования в секундах, по умолчанию `90`
- `IPAM_SCAN_TIMEOUT_MS` — таймаут одного `ping`, по умолчанию `1000`
- `IPAM_SCAN_CONCURRENCY` — число параллельных `ping`, по умолчанию `32`
- `IPAM_HISTORY_LIMIT` — сколько последних событий истории отдавать в UI, по умолчанию `200`

Пример запуска на другом порту:

```bash
IPAM_PORT=4180 python3 server.py
```

## Где хранятся данные

- все данные лежат в серверной `SQLite`-базе
- по умолчанию база создается в `data/ipam.db`
- каталог `data/` исключен из git через `.gitignore`
- чистая установка получается автоматически, если в репозитории нет `data/ipam.db`
- для полного сброса можно удалить файл базы или очистить данные через UI

Это значит, что один и тот же IPAM можно открыть с ноутбука, телефона или другого ПК, если они подключаются к одному серверу.

## Что хранится в базе

- подсети
- группы диапазонов
- устройства
- результаты `ping`-проверок
- история изменений IP

## Группы диапазонов

Группы помогают делить одну подсеть на логические зоны, например:

- `2-4` — `hypervisor`
- `5-19` — `VM`
- `20-29` — `Home Assistant`
- `30-39` — `WLED`

Особенности:

- группа всегда принадлежит конкретной подсети
- для подсетей вида `/24` можно вводить только последний октет, например `2` и `4`
- диапазоны внутри одной подсети не должны пересекаться
- после создания группы приложение сразу запускает `ping`-проверку этого диапазона и показывает, сколько адресов занято и сколько свободно

## Автоматизация v0.2

- сервер периодически выполняет фоновый `ping` по пулам адресов
- кнопку `Проверить ping` можно использовать для ручного запуска скана
- при создании группы можно сразу проверить занятость только ее диапазона
- при добавлении устройства интерфейс подсказывает первый свободный IP
- изменения от других клиентов приходят через live-канал без ручного обновления страницы
- поле `Оператор` в интерфейсе используется для истории событий и хранится локально в браузере как пользовательская настройка

## Импорт и экспорт

Поддерживается:

- `JSON` — полный снимок состояния
- `CSV` для подсетей
- `CSV` для групп диапазонов
- `CSV` для устройств

В `JSON` входят:

- `subnets`
- `groups`
- `devices`
- `scanResults`
- `history`

При импорте можно заменить текущее состояние или объединить его с новым.

## Текущие ограничения

- нет DHCP-интеграции
- нет SNMP, ARP или полноценного автообнаружения устройств
- `ping` показывает только факт доступности IP, но не тип устройства
- редактирование записей пока не реализовано, доступно удаление и повторное создание
- авторизация пользователей пока не добавлена
- при одновременном редактировании одних и тех же сущностей несколькими людьми нет сложного механизма разрешения конфликтов
